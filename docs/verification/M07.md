# M07 — Mock 持久化会话验收

日期：2026-10-15。范围：持久化私有会话、LangGraph PostgreSQL checkpoint、持久化 SSE、取消、删除与中断恢复。真实模型、RAG、兼容性 Agent 工具和装机审批不在本次范围。

## 实现与事实源

- `backend/app/chat/` 分离 API、状态存储、图执行、工作线程和删除清理；`models.py` 增加 chat_session、chat_run、chat_message、chat_event。
- `m07_001` 接在 m08_001 后，固定 checkpoint-postgres 3.2.0 的十条迁移；四张 SDK 表由显式迁移维护。迁移回退/升级保留此前用户表记录。
- chat_message 是展示历史事实源；checkpoint 是运行状态，不把失败执行中的 checkpoint 当作完成答案。内部 thread_id 服务端生成且不返回客户端。
- LangGraph 1.2.15 / checkpoint-postgres 3.2.0 已锁定。有限 Mock 上下文只保留最近六条问题、上一完成报价的商品引用；引用必须在同会话完成运行的报价中存在。
- 创建与发送用 client_request_id 去重；更换请求内容返回 409。数据库部分唯一索引限制一个活动运行，advisory lock 防止取消后旧工作线程与新运行、清理任务互相穿透。
- 用户消息和助手答案追加均推进会话版本，旧删除预览遇到新答案提交返回 409。完成答案、结果和答案分片事件同事务写入。

## 恢复、流式与清理

SSE 每个事件携带 run_id 与递增事件 ID，支持 after_event_id；工具事件在真实工具调用前后保存。message.delta 是完成答案的持久化分片，不是实时模型 token。传输最多十五秒，客户端断线后 GET 状态与历史，不自动重发 POST。运行截止六十秒；进程中断后，仅在截止且无工作锁时标记 INTERRUPTED，不重执行。SQL 超时三秒、锁等待一秒、连接池等待两秒；这些与 M06 工具预算分别约束。

取消后旧线程不能提交助手消息。删除先校验 owner/tenant 与 expected_version，标记删除后立即 404，再清理消息、运行、事件和 checkpoint。清理失败保留 PENDING，可运行 `cd backend && uv run --locked python -m app.chat.cleanup` 重试；单项失败不阻塞其他项。最小删除记录删除满七天且内容清理 DONE 后在后续清理任务移除；尚无周期任务调度器。

## 限制与下一阶段

Mock 不证明真实 LLM 理解质量；每会话 100 次运行、每用户每租户 30 个活动会话。数据库并发准入跨进程，但 M06 频率限制仍为进程内实现。后台工作不是持久任务队列，崩溃运行明确失败而非自动续跑。外部 tracing 关闭，日志不输出聊天内容或异常原文。价格继续是历史 USD，兼容性未知不转 PASS。

建议下一阶段补齐 M08 Agent 兼容性工具接入，再进入 M10；本次不自动实施。
