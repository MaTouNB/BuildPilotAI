# M08 补充验收：Agent 只读兼容工具

日期：2026-10-16。承接 M07，补齐提前实施 M08 时保留的 Agent 接入，不进入 M10。

## 范围与变更

- `backend/app/agent/tools.py` 新增严格 BuildID schema 和服务端认证闭包；仅有闭包时注册 check_compatibility。独立工具事务重新鉴权、过滤本人当前租户草稿、锁定核对版本，复用 M08 report。没有写 Build、条目、快照或规格的代码。
- provider 支持固定格式 `检查方案 <UUID> 版本 <正整数> 的兼容性`，不猜方案；runtime 只把真实工具返回加入 compatibility_reports，忽略模型兼容断言。所有原有次数/大小/超时限制继续适用。
- M06 无状态入口与 M07 graph/worker 均注入当前请求的可信认证闭包。身份不进模型参数或 checkpoint；报告沿既有私有历史、事件、运行与删除机制保存。
- 前端从 CompatibilityReport 提取纯展示 CompatibilityEvidence，会话复用规则/缺证据/来源/未覆盖项。工作台给出当前版本问题文本，历史报告明确标注旧检查记录不等于当前报告。
- 无新增依赖、数据库迁移、真实模型或 API Key。

## 实际浏览器链路

1. 登录已有本地测试账户，打开本人原有方案（仅选 CPU，版本 2）。展开工作台的当前版本问题并发送到独立新建验收会话。
2. 运行实际 check_compatibility 一次，页面显示版本 2、m08.1、检查时间及 UNKNOWN。CPU socket=AM5 来自此前批准的审核证据；缺少主板、内存、显卡/机箱等组件，未升级为 PASS。
3. 工具轨迹显示真实 build_id/expected_version 参数与规则返回；页面列出 BIOS/QVL/供电等未检查项。
4. 不修改方案，发送旧版本 1 的问题；页面提示版本/权限/不可用，未返回第二份报告。
5. 刷新页面后正确报告和拒绝记录均恢复；原方案仍版本 2、小计 USD 451.50，历史来源口径不变。
6. 375/768 像素视口宽度与页面 scrollWidth 相等；检查记录文字正常折行，视口随后恢复。最后浏览器 error/warn 为空。

```bash

make check
make check-db
```

在工作台选择本人草稿，复制「在会话中检查此版本」的问题发送；核对报告版本/规则/缺失字段/来源，再使用旧版本复核不返回报告。不要为演示修改真实审核规格，也不要把原始商品规格当作已审核证据。

## 限制与下一阶段

仍为有限 Mock；不是自由语言理解或真实 LLM 的验收。真实目录 CPU/GPU 覆盖不足，主板 DDR、空间等证据未补齐；合成 PASS/FAIL 测试不代表真实整机已验证。报告是历史快照，后续方案或规格变更必须重新检查。仅三项规则，PASS 不能证明 BIOS 或整机兼容。无方案选择/推荐/生成/修改/审批工具。
