# M05｜登录、租户与私人方案隔离

日期：2026-10-15。结论：本地登录与权限隔离闭环通过。没有进入后续里程碑。

## 变更与架构

- app/auth.py：Argon2密码校验、数据库opaque会话、登录/退出/me/租户选择、CSRF/Origin/Host限制、数据库登录限流、Public Identity响应契约。
- app/builds.py：替换固定Demo作用域，使用认证Actor；读写按当前用户和租户检查，写事务再次鉴权，幂等重放也验证资源归属。
- models.py、m05_001迁移：password_hash、成员关系、会话、限流表；原Demo数据未改变或转给登录账号。
- app/seed_accounts.py：仅本地开发初始化，随机生成密码写0600的data/local/m05-accounts.json；拒绝覆盖、符号链接目录及已存在账号，无密码/哈希输出。CLI不会申请第三方权限。
- AuthContext.tsx/auth-state.ts/api.ts/App.tsx：登录守卫、身份栏、租户选择、内存CSRF、退出/401清理、旧身份响应保护；BuildWorkspace通过相同客户端写入，保留M04 Diff/版本/幂等流程。
- .env.example默认关闭Demo；Secure Cookie默认开启，本地HTTP显式关闭并限loopback。本地.env未提交。

依赖新增argon2-cffi==25.1.0，锁文件包含传递依赖。实现参考[FastAPI密码哈希说明](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)、[Argon2 PasswordHasher](https://argon2-cffi.readthedocs.io/en/stable/api.html)、[Starlette Cookie API](https://starlette.dev/responses/)。保留原FastAPI栈，没有接入Next.js或托管认证服务。

## 手工验收与运行

`make setup`、`make db-up`、`make db-migrate`；backend目录执行`UV_CACHE_DIR=/tmp/buildpilot-uv-cache uv run --locked python -m app.seed_accounts`，再`make dev`。旧.env补AUTH_COOKIE_SECURE=false（本地HTTP）并重启；DEMO_ENABLED不再开放访问。

打开5173工作台，读取本地密码文件登录，创建方案；在另一账号或租户尝试复制方案ID，统一404；退出后请求私人接口应401。种子命令若账号或输出文件已存在则拒绝覆盖，不能当重置密码工具。

## 已知边界

没有开放注册、密码重置、MFA、管理成员UI、密码更改/API密钥登录、聊天或Agent。admin没有默认私有读取特权。会话8小时绝对过期，服务端撤销/成员状态每次检查；过期行清理、全面审计、生产代理/TLS配置和系统限流仍属于后续运维。当前实现不是对公网生产安全的全面认证。
