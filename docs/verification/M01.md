# M01 文件 ETL 实施与验收

日期：2026-10-13（Asia/Shanghai）。分支：milestone/m01-etl。仅文件处理，未实施 M02 数据库导入。

## 实现与边界

- backend/app/etl/source.py：只读 ZIP、哈希校验、确定性记录键、逻辑记录序号及物理起止行。
- normalizers.py：名称/金额/八类规格解析，保留未知字段和源值；格式错误 ERROR，缺失/疑似异常 WARN。
- pipeline.py：审计统计、疑似重复/同名不同规格/价格冲突诊断、隔离输出及受保护的文件替换。
- profile.py / clean.py：两个 CLI；dry-run 只生成报告，不写数据库、不删除已有完整输出。
- backend/tests/etl/test_pipeline.py：自产合成 ZIP fixtures；测试不依赖原始第三方数据或模型服务。
- scripts/check_m01.py：仅本地执行的原始数据全量验收。README、ETL 设计和路线已同步更新。

candidate_key 不是 SKU；没有合并任何源行。所有 is_quotable=false，合法历史金额与允许严格预算报价分开。M02 才建立目录身份及选价，不能把本阶段输出当成已审核商品目录。时钟等单位不明字段保留源值，不猜单位。

## 手工验收

1. 根目录运行 `make check`。
2. 确认本地 data/raw/csv.zip 存在，再运行 `python3 scripts/check_m01.py`。
3. 查看 data/processed/m01/quality_report.json 及 quarantine.jsonl，按源行号回查。
4. 在 backend 目录用 README 命令运行 dry-run，确认独立报告目录没有 JSONL。
5. 给输出目录添加个人文件，再清洗应拒绝替换；使用新的专用目录继续，不要删除个人文件。

## 限制与下一阶段

没有数据库入库、规范 SKU 审核、最终报价选择或兼容结论。全量验收依赖本地原始 ZIP，CI 只测合成 fixtures。不支持同一输出目录并发导出；内存读取策略适用于当前 66k 数据规模，扩展大小限制 128 MiB。尚未做频率单位的外部证据核实。
