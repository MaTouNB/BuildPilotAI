# M04 学习笔记

## 为什么要快照

装机条目保存具体报价ID、USD金额、来源与数据集日期。目录后来选了新价格，已经保存的方案仍使用旧快照；数量变化只乘旧金额，换成不同商品才取新报价。缺价保存null，不能补成0参与完整报价。

总价用Decimal按条目相乘再相加。内存套装quantity=1时一套价格只计一次，不能因为modules=2再乘2。当前小计可能超预算但仍允许存草稿，是否组件完整和价格完整是两个独立判断。

## 版本和幂等

版本保护不同修改之间的竞争：两个请求都基于版本3，只有一个能把它改到4。幂等保护同一个请求的重试：服务器已保存但响应丢失时，客户端用同一键和同一请求体重试，读取持久化结果，不再写一次。

请求键锁、版本行锁、快照和请求结果在同一事务里。已确认报价ID还是前端所见源价的校验条件；不是让客户端决定权威金额。选价与ETL共用锁，变化时409要求重新预览。

## Demo 边界

固定tenant/user外键让未来认证迁移有归属基础，但不意味着登录已实现。所有本地操作者共享专用Demo身份，不能拿请求体中的owner字段做授权。关闭Demo应立即禁止装机访问，旧方案仍属于Demo，不自动归给后来的账户。

## 练习

1. 在两个页面打开同一方案，分别修改并观察版本冲突。
2. 模拟保存响应丢失，解释为什么相同键必须携带相同请求体。
3. 从只含CPU/GPU的草稿解释“价格完整”“组件完整”“兼容UNKNOWN”为何可同时成立。
