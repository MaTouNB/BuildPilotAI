# M01 学习笔记与练习

## 三个设计决策

1. **先保留，再诊断。** read_source 读取原始 ZIP，raw.jsonl 留下全部源行。candidate_key 根据类别、规范名称和非价格规格产生，只用来查疑似重复。相同名称可能对应不同容量或颜色，因此程序不按名称合并；同样不认为候选哈希就是稳定 SKU。
2. **金额交给 Decimal。** parse_price 接收源字符串，拒绝 NaN/Infinity/非正价，按 ROUND_HALF_UP 明确舍入到两位小数。空价返回 None；JSON 输出字符串或 null，避免小数金额经过浮点转换。舍入有警告，原值仍在 raw_data。
3. **错误有去向，导出有边界。** 每条记录保存 issues；ERROR 输出到 quarantine，WARN 可以保留但不补未知事实。写文件先生成临时目录，再替换工具自己的目录；哈希不匹配、raw 路径、外来文件和 dry-run 覆盖完整输出均拒绝。

## 核心语法与调用链

- `with ZipFile(...)` 和 `with archive.open(...)`：离开作用域后关闭资源。没有 extractall，因此不会把 ZIP 路径写到磁盘。
- `csv.DictReader`：表头映射到字段，额外列或缺列单独记录。logical row number 是记录序号，line_num 是物理行号，含换行的 CSV 字段会让两者不同。
- `Decimal(text)` 与 `quantize`：用十进制表示金额并明确舍入。CSV 没有值不等于金额为零。
- `Counter`、`defaultdict`：按文件/类别累计数量、按候选键归组；只生成诊断，绝不因此删除源记录。
- `zip(raw, normalized, strict=True)`：源行与清洗行长度不一致时立即报错，防止默默少处理一部分数据。

调用链：CLI 参数 → 输入 hash → ZIP/CSV 只读解析 → 名称/规格/价格解析 → 重复与冲突诊断 → 报告/清洗/隔离文件 → 本地验收脚本核对基线及文件 hash。

## 三个手动练习

1. 给 parse_price 编写三个额外测试：带空白、边界舍入、非法值；解释为什么 Infinity 不能作为合法价格。
2. 用自行编写的 ZIP fixture 做两条同名内存，一条 2×16 GB，一条 2×32 GB。解释它们为什么不能合并，找出 candidate_key 不同的字段。
3. 在测试 fixture 中给一条内存写 speed='5,0'。运行 pytest 后确认它进入 quarantine；再改成空字符串，解释为何“缺少证据”和“非法格式/数值”的处理不同。

## 本次故障与修复

检查 dry-run 语义时发现：如果用同一个目录覆盖完整清洗输出，只保留报告会删除旧 JSONL。已改为拒绝此操作，要求独立报告目录，并用测试验证旧文件保持一致。
