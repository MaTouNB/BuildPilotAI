# M07 学习笔记

会话标识由公开 session_id 映射到服务端内部 thread_id，再映射到 PostgreSQL checkpoint。session 的 owner/tenant 每次从认证上下文校验；知道标识不等于有访问权。checkpoint 保存图状态，chat_message 保存用户可见历史，chat_run 保存执行终态，chat_event 保存可恢复事件。

幂等与并发解决不同问题：client_request_id 阻止同一次发送重试创建第二个运行；数据库唯一索引阻止同会话同时活动；advisory lock 把执行与删除清理串行化。取消并不强制杀死 Python 线程，必须在提交时再次检查运行状态和权限。

流式连接可能早于运行结束关闭。客户端应查询已持久化状态和历史，不能因为没收到完成事件就重新 POST。答案分片在完成事务中保存，不能把它称作实时模型 token。checkpoint 恢复也不能把未提交的输出伪装成完成历史。

删除采用两步：立即撤销访问，然后可重试地清理内容。删除确认携带版本，用户或助手追加消息都会使旧预览失效。最小删除标记满足七天与清理完成条件后，由维护命令移除。

## 三个练习

1. 画出 session、run、message、event 与内部 checkpoint 的关系，指出每个查询在哪一步检查用户和租户。
2. 关闭服务再重启，验证完成历史恢复；模拟未完成运行到期，解释为什么明确失败而不自动重复执行。
3. 取消运行后延迟放行模拟工具，同时重试发送与删除，验证旧线程不能追加答案；再模拟清理失败并重试。
