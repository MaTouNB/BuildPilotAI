# M02 学习笔记

## 三个核心设计

1. **staging 与规范目录分开。** raw_import_row 保存原始字典和 normalized_data；未核对身份时 part_id=NULL。审核映射才创建 hardware_part / part_source_map。名称不是唯一 SKU，源记录键也不是跨数据版本的商品身份。
2. **事务与失败记录分开。** 数据/映射/价格/问题在一个 connection.begin() 中写入，异常则整体回滚。import_attempt 的失败状态随后用独立事务保存；否则回滚会连错误证据也一起丢失。
3. **幂等有数据库边界。** input SHA + pipeline version 唯一批次，artifact 指纹阻止同版本悄悄改变结果；advisory lock 使并发同批次请求串行。显式选价保持旧价格行，记录旧/新 ID，并用部分唯一索引限制一个当前可报价来源。

## 调用链与语法

import_db CLI → load_artifacts 校验 → Pydantic 审核文件 → make_engine → 锁批次 → 元数据/attempt 事务 → payload 事务 → 统计与状态 → 解锁。

- Mapped[T] / mapped_column 定义 Python 类型与 SQL 类型；Decimal 对应 NUMERIC，dict 对应 JSONB，None 对应允许缺失的字段。
- insert(...).on_conflict_do_nothing 避免重复 ID，但不能代替输入版本校验和事务；同版本内容变动会主动报错。
- connection.begin() 在正常结束时提交、异常时回滚；把代码分成两段事务才能同时保留失败记录。
- select / update 参数绑定；CLI 不拼接业务 SQL。测试 schema 名由随机 UUID 生成，清理仅针对自己创建的 schema。
- NULL 不是 0，SQL 用 IS NULL 查询缺价；不能依赖普通等于 null 比较。

## 本次定位的问题

普通价格大于零约束不足以拒绝 PostgreSQL numeric NaN。已单独加入有限值约束，并用真实 PostgreSQL 更新测试确认拒绝；参考 [官方数值类型说明](https://www.postgresql.org/docs/17/datatype-numeric.html)。
