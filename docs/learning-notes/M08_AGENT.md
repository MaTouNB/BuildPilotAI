# M08 Agent 工具接入学习笔记

工具参数可以指定希望检查的 build_id，但不能决定该方案是否允许读取。服务端捕获认证上下文，在工具实际执行时重新鉴权，然后查询本人当前租户的草稿。权限与输入格式是两道不同检查，UUID 合法不等于有权限。

expected_version 把报告绑定到用户看到的方案版本；锁定方案后核对版本，再读取条目和审核规格。报告同时记录规则版本和检查时间。保存到会话的报告是历史检查快照，规格变化不会改写原消息，需要重新调用工具。

Mock 负责产生结构化调用，Python 规则引擎负责事实结果，界面负责展示证据。三者分工使模型的一句“完全兼容”无法产生 PASS。COMPATIBILITY_CHECKED 仅表示取得报告，报告可能是 UNKNOWN 或 FAIL。

练习：
1. 同一方案用旧版本请求，观察没有报告且提示刷新；确认方案版本和金额未变化。
2. 用另一个用户或租户请求该 UUID，比较不存在与无权结果，确认没有泄漏规格证据。
3. 将 CPU 插槽审核证据加入后观察 UNKNOWN，解释为什么仅有 CPU socket 不能证明 BIOS 或整机兼容。
